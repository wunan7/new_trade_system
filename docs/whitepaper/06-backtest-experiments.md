# 6. 回测框架与实验记录

## 6.1 回测引擎设计

**类型**：事件驱动日级回测（逐日模拟完整交易流水线）

**防偏差机制**：
- **无前瞻偏差**：因子使用当日收盘价计算，信号 T 日生成，T+1 日可执行。舆情数据使用 T-1（前一天）
- **真实交易约束**（V6起）：涨停板不可买入、跌停板不可卖出、停牌不可交易
- **完整成本模型**：佣金 + 印花税 + 滑点，每笔交易约 0.12%

**基准**：沪深300指数

## 6.3 每次迭代的因果分析

### V1→V2（+32.49%）：数据修复

**根因**：`stock_valuation` 表 2023-2025 年完全无数据，导致 PE/PB/股息率因子全为 NULL。价值策略依赖这些因子，在数据缺失下仅产生 13 个信号（占0.4%），系统退化为单一动量策略。

**修复**：补全 3 年估值历史数据。

**效果**：价值策略信号从 13 暴增至 536（41倍），系统从单策略退化恢复为多策略均衡。

**教训**：**数据完整性是量化系统的生命线**。在系统层面应有数据质量监控，自动检测因子覆盖率异常。

### V2→V3（+11.78%）：代码修复

**根因1**：`events.content` 字段中净买入金额标注"万元"但实际存储单位是**元**。`min_net_buy=500`（意图500万元阈值）实际只过滤了500元以下的记录。

**根因2**：模拟盘 19:30 运行时舆情数据尚未入库（~22:00生成），导致舆情因子永远为空。

**修复**：
1. `min_net_buy` 从 500 → 5,000,000（正确的500万元）
2. 舆情查询从当天改为 T-1 + 7天回溯窗口

**效果**：事件驱动信号从 8 增至 574（72倍），舆情因子首次生效。

**教训**：**数据单位和时序是量化系统中最隐蔽的bug**。应在数据入库时验证值域合理性。

### V3→V4系列（全部失败）：参数调优的局限

三次实验（仓位提升、权重调整、止损调参）均未超过 V3。

**教训**：**当系统架构和数据确定后，参数空间的边际收益极小**。进一步提升需要新的信息源或策略创新，而非调参。

### V5系列（IC/IR因子评估）：方向正确，方法需精细

- **IC评估本身非常有价值**：揭示了A股反转效应和基本面因子失效的重要市场特征
- **IC作为硬过滤条件失败**（V5a/b）：高IR因子（如上影线比）用来过滤候选股时，会误杀各策略的核心候选
- **IC作为confidence调整有效**（V5c）：仅调整信号权重而非直接过滤，胜率+2%、盈亏比+0.14

**教训**：**因子有效性评估应用于信号加权，不宜作为硬性过滤条件**。因子在截面上的统计有效性和个股层面的适用性是两码事。

### Phase 1（涨跌停约束）：真实基线的建立

加入 trade_constraints 后，V3 的 +24.41% 降至 +11.22%。

**分析**：V3 中约一半收益来自涨停板买入（实际无法成交）和跌停板卖出（实际无法卖出）等虚假交易。

**教训**：**无交易约束的回测结果必然过于乐观**。任何量化系统发布前必须加入涨跌停/停牌约束。

### Phase 3 事件扩展（核心突破）

**Phase 3a 失败**（+7.95%）：负面事件信号（earnings_miss + lock_up_expire）产生 direction=-0.5 的信号，在聚合时拉低了正向信号，导致动量策略从 545 次崩塌到 13 次。

**Phase 3b 失败**（+7.44%）：去掉负面信号后，事件信号仍占 74%（回溯期太长：earnings_beat 30天、buyback 30天），挤占了其他策略的信号配额。

**Phase 3c 成功**（+24.60%）：
1. 缩短回溯期（earnings_beat 30→7天，buyback 30→10天）
2. 每类事件设 `max_signals` 上限（龙虎榜10、其余5）
3. 负面事件（earnings_miss、lock_up_expire）不参与信号生成

**教训**：
- **负面信号不应混入正向信号的聚合**，它们适合作为独立过滤器
- **事件信号数量必须限额**，否则会挤压其他策略的生存空间
- **事件回溯期越短越好**——信息的衰减速度远比想象中快
