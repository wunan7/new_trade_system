# V6.1 执行层优化总结

**日期**: 2026-05-05  
**基线版本**: 当前主线代码基线（回测：+26.77%，夏普0.72，交易3690笔）  
**目标**: 针对 2026 年 4 月模拟盘暴露出的交易经济性问题，优化执行层约束，减少低质量交易与成本侵蚀。  

---

## 1. 实施内容

本次仅做 **A 类执行层优化**，不改因子体系、不改主策略框架、不改市场状态检测器。

### 已实现的 5 项

1. **最小下单金额约束**
   - 当前值：**6000 元**
   - 含义：预计成交金额低于 6000 元的订单直接不下单

2. **统一冷却期（cooldown）**
   - 当前值：**2 个交易日**
   - 含义：股票卖出后 2 个交易日内不允许重新买入

3. **event 成本感知过滤**
   - 当前值：最小预期收益 **1.5%**（或至少大于单边成本×3）
   - 含义：边际收益空间不足的事件信号不进入交易队列

4. **低价股小仓位禁入**
   - 当前规则：股价 < 8 元 且下单金额 < 10000 元，不下单

5. **自动月度交易归因报表**
   - 新脚本：`scripts/monthly_trade_report.py`
   - 输出：`docs/monthly-reports/YYYY-MM-paper-trading-report.md`

## 2. 调参过程

### 第一版（过严）
- 最小下单金额：10000
- cooldown：5天
- event 最小收益：2.0%

- event 最小收益：1.5%

**结果**：
- 总收益：+19.86%
- 夏普：0.62

结论：方向正确，但收益恢复仍不够。

### 第三版（最终 V6.1）
- 最小下单金额：**6000**
- cooldown：**2天**
- event 最小收益：**1.5%**
- 低价股最小金额：**10000**

**结果**：见下一节。

## 4. 结果解读

### 4.1 有效的地方

V6.1 已经实现了预期目标中的大部分：

- **交易数从 3690 降到 2382（-35%）**，明显减少了低质量换手
- **胜率几乎不变**，说明过滤掉的主要是低质量交易，而不是高质量交易
- **盈亏比完全不变（1.67）**，说明核心交易质量没被破坏
- **夏普只小幅下降 0.04**，说明单位风险收益能力基本保住了

### 4.2 付出的代价

- 总收益下降了 3.13%
- 说明减少的 35% 交易中，仍然有一部分是有正 alpha 的

换句话说：

> V6.1 的本质不是“让系统更赚钱”，而是“让系统以更少的交易，换取几乎相同的交易质量，并降低执行层噪声”。

这是一个**交易经济性优化版本**，不是纯收益最大化版本。

## 5. 月度归因能力

4 月月报脚本已经成功生成，并量化出关键问题：

**2026-04 月报结果**：
- 总交易：84 笔
- 小额交易（<1万元）：76 笔
- 总佣金：420.00 元
- 总印花税：209.76 元
- 总滑点：110.04 元
- 总交易成本：739.80 元
- 成本 / 毛收益比：13.66%

这说明执行层优化的方向是完全正确的——4 月的核心问题就是：

- 小单过多
- event 交易偏碎
- 交易成本吞噬收益明显

## 6. 当前建议定位

### 适合作为：
- **执行层优化分支版本**
- 未来继续调优成本感知仓位 / 冷却期策略的基础版本
- 模拟盘复盘分析的标准版本

### 不建议直接替代当前收益最强主线的原因：
V6.1 的总收益仍低于当前主线基线，因此如果目标是“纯收益最大化”，还不能直接把 V6.1 当作绝对主版本。

但如果目标是：
- 更少的交易
- 更清晰的执行纪律
- 更接近真实可落地的系统形态

那么 V6.1 是一个很有价值的分支版本。

---

## 7. 后续建议

下一步建议从 **B 类项目** 中挑最相关的继续推进：

1. **成本感知仓位**
   - 不是简单过滤，而是根据成本占预期收益比例自动缩小仓位
   - 这比“硬阈值过滤”更柔和，可能有机会找回部分收益

2. **策略专属冷却期**
   - event 保持 2天
   - momentum 可能只需要 1 天
   - value/growth 可能需要更长

3. **event 上限再优化**
   - 当前 event 仍是主导信号来源
   - 后续可单独回测其最优 max_signals 配置

---

## 8. 结论

V6.1 不是一版“收益最强”的版本，而是一版：

> **在尽量不明显伤害收益的前提下，显著降低交易频率、提升执行层纪律性、并补齐自动归因能力的执行层优化版本。**

如果把 V6 看作“收益驱动版本”，那么 V6.1 可以看作：

> **更成熟、更克制、更容易往真实交易系统演进的版本。**
